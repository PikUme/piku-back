# 챕터형 회원가입

- Status: 구현 계약, 기본 비활성화
- Audience: 백엔드 개발자
- Source of Truth: Yes
- Last Reviewed: 2026-09-21

## 가입과 기존 계정

이메일·비밀번호 로그인을 유지한다. 신규 가입은 인증 → 필수 동의 → 닉네임·캐릭터 설정 순서다. 화면 제출 단위로 API를 제공하며, 페이지 진입이나 입력 변경으로 가입 레코드·이벤트를 발행하지 않는다.

인증 성공 후 DB에 10분짜리 가입 증명을 저장한다. 이 단계에는 아직 회원이 없다. 이메일을 확보하고 필수 약관에 동의하면 하나의 DB 트랜잭션에서 실제 User, 동의 기록, 필요한 외부 계정 연결을 생성하고 증명을 소비한다. 최초 닉네임은 검증된 이메일 기반의 고유한 기본값을 사용하며, 캐릭터는 Character 카탈로그의 `base_image_1.webp`에 대응하는 실제 ID를 참조한다. 기본 캐릭터가 없거나 모호하면 회원 생성 전체를 취소한다.

회원 생성 후 상태는 `REQUIRED`다. 저장된 기본 닉네임과 기본 캐릭터를 그대로 선택해도 되며, 닉네임·캐릭터를 함께 명시적으로 제출해야 `COMPLETED`로 전이한다. 닉네임을 수정했다면 3분 유효 예약이 필요하다. 과거 `가입대기_` 임시 닉네임은 그대로 확정할 수 없다. 회원 생성 후 프로필 완성에는 가입 증명의 10분 제한이 적용되지 않는다. 중단한 회원은 보존되며 다음 로그인에서 같은 userId로 재개한다.

동의·로그인·본인 조회 응답은 회원에 저장된 `characterId`를 제공한다. 신규 회원은 기본 캐릭터의 실제 ID를 받으며, 새로고침 후 본인 조회로 선택을 복구해 변경 없이 완료할 수 있다.

로그인하지 않은 진행 조회에서 만료·무효·구 가입 증명 또는 탈퇴·삭제 회원의 잔존 증명은 인증 시작 상태로 복구하고 웹의 남은 증명 쿠키를 정리한다. 증명 쿠키 수명은 DB 만료까지 남은 시간만 사용한다. 이미 회원이 생성됐지만 세션을 잃었으면 기존 회원 ID와 재인증 상태를 안내하고 기존 로그인으로 재개한다. 인증된 회원의 진행은 현재 User 상태가 우선한다.

다른 이메일로 가입을 다시 시작할 때는 기존 코드 발송 API에 인증 재시작 의도를 명시한다. 발송 성공 후 이전 증명을 정리하고 새로운 이메일 인증 시도를 사용한다. 소셜 가입 이메일은 직접 수정하지 않으며, 이미 만들어진 회원을 삭제하거나 발송 제한을 초기화하지 않는다. 기존 이메일 로그인 및 로그아웃 성공 시 이전 가입 증명을 정리한다.

기존 회원은 마이그레이션에서 `COMPLETED`가 된다. 탈퇴 시각을 변경하거나 과거 약관 동의 기록을 만들어내지 않는다.

## 데이터와 트랜잭션

| 데이터 | 소유와 제약 |
| --- | --- |
| `users.profile_setup_status` | User가 소유하는 `REQUIRED` / `COMPLETED` 상태 |
| `signup_authentications` | 가입 증명·호출자 해시, 인증된 이메일, 임시 비밀번호 해시, 고정 만료 시각, 소비 결과와 재요청 지문 |
| `user_oauth_accounts` | 제공자+subject 고유, 회원+제공자 고유. subject는 대소문자·공백을 임의 정규화하지 않음 |
| `user_agreements` | 실제 동의한 문서 종류·버전·내용·동의 여부·시각 |
| `verification`의 가입 challenge | 요청·호출자·이메일·목적 결합, 시도 횟수, 발송 및 재발송 상태 |
| `nickname_holds` | 닉네임·회원 고유, 고정 3분 만료. 회원당 하나의 예약 |
| `nickname_write_mutex` | 동의 시 기본 닉네임 생성·기존 가입·프로필 변경·신규 점유·가입 완료의 닉네임 경쟁을 직렬화 |
| 발송 제한 테이블 | 새 요청 ID를 만들어도 우회하지 못하는 이메일 및 요청 출처 제한 |

가입의 영속 상태와 정확성은 DB에 의존한다. Redis 장애로 가입 증명·회원·닉네임 점유가 유실되는 구조를 사용하지 않는다. DB 장애 시 가입 쓰기는 실패하며 다른 저장소로 임의 우회하지 않는다.

동의는 회원·동의·소셜 연결·증명 소비를 함께 커밋한다. 같은 증명과 같은 동의 내용의 재시도는 같은 회원으로 복구된다. 다른 내용으로 소비된 증명을 재사용하지 않는다. 프로필 완료는 닉네임 검증·회원 변경·완료 상태·예약 해제를 함께 커밋한다. 같은 최종 값의 재시도만 성공으로 취급한다.

인증·동의·재발송는 DB 잠금을 기다린 뒤에도 유효기간을 확인한다. 요청을 만료 전에 보냈다는 이유만으로 만료 후 처리를 허용하지 않는다. 잠금 아래 유효성이 확인된 쓰기는 이후 만료되더라도 완료할 수 있으며, 만료 정리가 생성된 회원·동의나 새 유효 인증 자료를 지우지 않는다.

닉네임의 앞뒤 공백은 `Nickname`에서 정리하며, 정규화된 같은 값으로 중복 검사·예약·저장·응답을 처리한다. 프로필 완료는 앞뒤 공백만 다른 재시도도 같은 최종 값으로 인정한다. 정리 후 빈 값·20자 초과·서버 전용 접두어는 거절하고 내부 공백은 유지한다. 기존 DB 값의 일괄 정규화는 이번 변경에 포함하지 않는다.

닉네임 비교는 기존 MySQL `users.nickname`의 대소문자·악센트 비교와 일치한다. 같은 예약을 다시 확인해도 만료 시각을 연장하지 않는다. 다른 닉네임 예약에 실패하면 이전 예약을 유지한다. 일반 프로필 수정과 구형 가입도 동일한 DB 잠금에 참여한다.

검증된 이메일의 local-part를 기본 닉네임으로 사용한다. `haru@example.com`은 `haru`가 되며 이메일 도메인은 포함하지 않는다. 점·`+tag`·대소문자는 보존하고 20자를 넘으면 앞부분을 사용한다. 기존 회원 또는 다른 회원의 유효 예약과 충돌하면 local-part를 최대 16자로 줄이고 1000~9999의 4자리 숫자를 붙인다. 빈 local-part나 `가입대기_` 접두어처럼 최종값으로 사용할 수 없는 경우에는 `사용자`를 기본 후보로 삼는다. 이메일 자체의 유효성 검증과 계정 식별 규칙은 변경하지 않는다.

프로필 입력란은 서버 응답의 `user.nickname`으로 미리 채운다. 정규화 후 본인에게 저장된 현재 기본 닉네임과 같으면 별도 중복 확인·예약 없이 캐릭터와 함께 완료할 수 있다. 수정한 닉네임에는 기존 3분 예약이 필요하다. 기본값으로 되돌려 완료하면 그 회원의 다른 예약도 같은 트랜잭션에서 해제한다. 본인 현재값으로 중복 확인 API를 호출해도 기존처럼 `nickname`, 유효한 `expiresAt`을 반환하며 null 만료 시각을 추가하지 않는다. 기존 `가입대기_` 닉네임을 쓰는 미완료 회원은 새 닉네임을 예약·선택해야 한다. 완료 API 제출 전에는 기본값을 가지고 있어도 `REQUIRED`와 이용 제한을 유지한다.

기본 닉네임 생성도 공통 DB mutex를 사용하며 회원·계정의 일반 조회 전에 획득한다. proof 잠금 → 닉네임 mutex → 증명 유효기간 재확인 → 조회·생성 순서로 처리하여 MySQL 반복 읽기에서도 직전 예약·생성 커밋을 확인한다. 기본 후보 1개와 숫자 후보 최대 19개를 검사하고, 후보 소진 또는 최종 DB 고유 제약 충돌은 기존 동의 전체 트랜잭션을 최대 3회 재시도한다. 끝까지 실패하면 `NICKNAME_COLLISION`이며 회원·동의·증명 소비를 남기지 않는다.

## 인증 경계와 접근 제어



User의 Application 유스케이스가 인증·가입·세션 발행을 조정한다. Security는 공개 User 조회 계약으로 현재 상태를 확인하고 토큰/HTTP 접근 제어를 담당한다. Character는 기본 캐릭터 해석을 소유하며 User가 임의 숫자 ID를 만들지 않는다. 웹·모바일의 쿠키·헤더·본문 차이는 HTTP 입력 어댑터에서 처리한다.

`REQUIRED`는 자신의 상태, 가입 프로필·닉네임, 기본 캐릭터 목록, 로그아웃·재발급·가입 중 탈퇴와 기존 공개 읽기만 이용한다. 회원 전용 쓰기, 푸시 등록, SSE 등의 경로는 완료 전 차단한다. 회원 전용 요청은 DB의 최신 완료 상태를 확인한다. 탈퇴 회원은 로그인·재발급에서 제외한다.

프로필 설정 전 회원은 공개 프로필, 검색, 다른 Context에 제공하는 회원 참조·요약과 활성 회원 집계에서 제외한다. ID를 직접 지정해도 공개 프로필을 반환하지 않는다. 누적 가입 통계에는 실제 생성된 회원으로 포함하며 본인의 인증·가입 재개 조회는 유지한다. 프로필을 완료하면 같은 userId로 공개 조회에 참여한다.

## 운영과 전달 범위

신규 가입은 기본 비활성화다. 실제 약관 문서와 버전, 기본 캐릭터와 클라이언트 전환을 준비한 후 활성화한다. `signup.enabled=true`에서는 구 가입 경로가 자동으로 닫힌다.

소셜 가입 증명·계정 테이블은 제공자 중립적인 공통 가입 기반이다. 이 변경에는 외부 인증 API, 제공자 토큰 검증, 기존 회원의 자동 연결 정책이 없다. 외부 로그인은 후속 변경에서 공통 가입 기반과 연결한다.

프론트·모바일 저장소의 구현 작업은 이 문서 범위에 포함하지 않는다.

## 소셜 이메일 필수 정책

모든 소셜 제공자의 신규 가입은 검증된 제공자 신원과 실제 제공된 유효 이메일을 필수로 한다. 이메일이 있으면 추가 서비스 코드 인증 없이 동의로 진행한다. 누락·빈 값은 `EMAIL_REQUIRED`, 형식·최대 255자·허용 도메인 실패는 `INVALID_EMAIL`이며 증명·회원 생성 없이 거절한다. `email_verified`·authoritative 사실은 기존 계정 자동 연결 보호 조건과 별도로 취급한다. 기존 subject 로그인·재인증 명시 연결과 엄격한 Gmail 자동 연결 정책을 완화하지 않는다. 다른 제공자의 실제 연동은 각 제공자 도입 작업에서 이 공통 조건을 적용한다.
