# Google 로그인

- Status: 구현 계약, 기본 비활성화
- Audience: 백엔드 개발자
- Source of Truth: Yes
- Last Reviewed: 2026-09-21

## 범위와 선행 가입 계약

기존 이메일·비밀번호 로그인을 유지하면서 웹·모바일 Google 로그인을 추가한다. 챕터형 가입이 제공하는 검증 증명·필수 동의·프로필 완료·공통 세션 계약을 사용한다. 인증·동의·프로필의 일반 가입 동작은 선행 변경에서 제공하며 이 변경은 Google 신원 검증, 소셜 가입 증명·동의 처리와 기존 계정 연결을 담당한다.

## Google 연결 규칙

검증된 `(provider, provider_subject)` 연결을 먼저 조회한다. 연결이 존재하면 그 회원을 사용하고 제공자의 이메일 변경으로 회원 이메일을 바꾸거나 다른 회원에 재연결하지 않는다.

연결이 없는 Google 신원은 검증된 Gmail과 기존 이메일이 일치할 때 기존 회원에 자동 연결할 수 있다. 기존 이메일 계정의 인증 가입 이력이 확인되었다는 운영 설정이 필요하다. 비밀번호가 없는 계정, 탈퇴 계정, 다른 Google 계정과의 연결 충돌은 자동 연결 대상에서 제외한다. Gmail의 영문 대소문자는 비교할 수 있지만 점과 `+tag`는 제거하지 않는다. 느슨한 DB 문자열 비교 결과만으로 연결하지 않는다.

일반 외부 이메일의 일치만으로 자동 연결하지 않는다. 충돌한 기존 회원은 기존 로그인 후 비밀번호를 다시 확인하는 명시적 연결 요청을 사용한다. 연결 목적과 대상 회원은 서버가 최초 요청에 묶고 콜백이 제출한 회원 ID를 받지 않는다.

신규 소셜 가입은 검증된 제공자가 반환한 이메일의 존재·형식·최대 255자·허용 도메인을 검사한다. 유효하면 Gmail·Workspace·외부 이메일 모두 별도 서비스 코드 인증 없이 동의로 진행한다. 누락·빈 값은 EMAIL_REQUIRED, 부적합은 INVALID_EMAIL로 실패하며 증명·회원은 만들지 않는다. email_verified·authoritative 사실은 기존 검증 Gmail 자동 연결 보호 조건으로만 사용하며 신규 가입 조건과 분리한다. 기존 subject 로그인과 재인증 명시 연결은 이메일 누락으로 막지 않는다.

Google로 신규 생성한 회원은 비밀번호가 없다. 비밀번호 재설정으로 비밀번호를 추가할 수 없으며 Google 로그인을 사용한다. 기존 이메일 회원에 Google을 연결하면 두 로그인 방법을 유지한다.

## 프로토콜과 저장 경계

`oauth_authorization_requests`는 state·호출자 해시, 암호화한 nonce·PKCE verifier, 목적·대상 회원·기기·등록 정보·상태·만료 시각을 저장한다. 요청 제한은 호출자와 출처 단위로 DB에 저장하며 새 state로 우회하지 못한다. V19는 이 자료 구조와 외부 계정 테이블 `user_oauth_accounts`, 가입 증명의 제공자·subject·이메일 검증 출처를 함께 추가한다. 선행 V16–V18은 이메일 가입·동의·프로필 스키마만 제공한다. 기존 이메일 가입 증명의 검증 출처는 `SERVICE`로 채우고 이메일·해시·만료·소비 상태를 보존한다.

Google 검증 어댑터는 공식 SDK의 서명·발급자·시간 검증과 명시적인 audience·authorized party·nonce 검증을 수행한다. 웹은 state와 PKCE S256, 모바일은 서버가 발행한 nonce와 등록 이름을 결합한다. 클라이언트가 임의 audience를 지정하지 않는다.

OAuth 요청은 짧은 트랜잭션에서 `PENDING` → `PROCESSING`으로 선점한 뒤 외부 교환을 수행한다. 네트워크 호출 동안 DB 트랜잭션을 유지하지 않는다. 성공은 `CONSUMED`, 실패는 `FAILED`가 되며 재사용하지 않는다. 네트워크 결과가 불명확하거나 처리 중 중단되면 새 로그인을 시작한다. 외부 제공자에 대한 exactly-once 보장은 하지 않는다.

웹 콜백은 고정 HTTPS 프론트 주소로 303 복귀한다. 토큰·가입 증명·원문 제공자 오류를 URL에 넣지 않으며 예상 가능한 실패는 제한된 `oauthError` 코드로 전달한다. JSON API의 실패는 공통 RFC 9457 Problem Details를 사용한다.

연결 저장과 OAuth 요청 완료 기록은 별도 커밋이다. 완료 기록 또는 응답 유실이 연결 롤백을 뜻하지 않는다. 같은 state를 반복하지 않고 새 state·nonce로 같은 subject를 재인증하여 이미 저장된 회원으로 복구한다.

## 활성화와 후속 범위

`signup.google.enabled`는 기본 false다. 실제 웹·모바일 Google 등록, 암호화 키와 프론트 복귀 URI가 준비되어야 활성화한다. 신규 가입 스위치와 독립이므로 가입을 중지해도 Google 기능이 켜져 있으면 이미 연결된 회원 로그인은 유지한다.

최초 Gmail 자동 연결과 명시적 연결도 신규 가입 활성화를 요구한다. 가입 중지 시 연결 없는 기존 이메일 회원의 최초 연결은 거절되며 이미 저장된 subject 연결 로그인만 유지한다.

실행 가능한 제공자는 Google뿐이다. 추가 제공자의 이메일 보증·subject 범위·토큰 검증·연결 해제와 회수 정책은 별도 작업이다. 프론트·모바일 저장소의 구현과 운영 활성화는 이 백엔드 PR에 포함하지 않는다.

## 소셜 가입 증명과 동의

소셜 가입 증명은 검증된 제공자와 subject, 유효 이메일을 고정 10분의 가입 증명에 보관한다. 제공자+subject와 회원+제공자 조합은 각각 고유하며 subject의 대소문자·후행 공백을 임의로 정규화하지 않는다. 동의 시 회원·실제 동의 기록·외부 계정 연결·증명 소비를 하나의 DB 트랜잭션으로 저장한다. 같은 subject의 동시 동의로 연결 충돌이 나면 성공한 연결의 회원을 새 트랜잭션에서 복구한다.

모든 소셜 제공자의 신규 가입은 검증된 신원과 실제 제공된 유효 이메일이 필요하다. 다른 제공자의 실제 연동은 각 제공자 도입 작업에서 이 공통 조건을 적용한다. 이메일을 별도로 입력하거나 서비스 코드로 보완하는 단계와 `VERIFY_EMAIL` 상태는 제공하지 않는다. 일반 이메일 가입으로 전환할 때는 기존 코드 발송 요청에 `restartAuthentication: true`를 사용하며 이전 소셜 증명의 이메일을 수정하지 않는다.
