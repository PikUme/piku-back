# 챕터형 회원가입 전환 운영

- Status: 활성화 전 운영 기준
- Audience: 백엔드·운영 담당자
- Source of Truth: Yes
- Last Reviewed: 2026-09-21

## 배포와 활성화 구분

코드와 스키마 배포만으로 신규 가입을 활성화하지 않는다. `signup.enabled`의 기본값은 false다. 실제 약관·기본 캐릭터·메일 전달과 클라이언트 전환을 확인한 후 기능을 연다. 이 문서는 운영 배포 승인을 의미하지 않는다.

## 필요한 설정

| 설정 | 기본값 또는 요구 조건 |
| --- | --- |
| `signup.enabled` | false. 새 인증·동의 가입 허용 여부 |
| `signup.legacy-signup-enabled` | true. 신규 가입이 활성화되면 자동으로 구 가입 차단 |
| `signup.agreements` | 실제 문서별 type, version, content, required. 유일한 종류·비어 있지 않은 본문·버전·필수 문서 검증 |
| `signup.max-code-attempts` | 5 |
| `signup.resend-seconds` | 60. 새 challengeId를 만들어도 같은 이메일의 재발송 제한 적용 |
| `signup.email-hourly-limit` / `origin-hourly-limit` | 5 / 30 |
| `signup.cleanup-interval-ms` | 3,600,000 |

## 전환 순서

1. DB 백업과 기존 이메일 회원 데이터를 확인한다.
2. `base_image_1.webp`를 해석하는 유일한 고정 Character와 표시 자산을 확인한다. 임의 숫자 ID나 가짜 기본 캐릭터를 주입하지 않는다.
3. V16–V18을 적용한다. 기존 회원은 `COMPLETED`로 보존하고 가입 증명·동의·제공자 중립적 연결 자료 구조·이메일 challenge·DB 닉네임 예약을 추가한다. 기존 동의나 계정 연결을 일괄 생성하지 않는다.
4. 모든 백엔드 인스턴스를 DB 닉네임 잠금과 미완료 회원 접근 제어를 사용하는 버전으로 교체한다. 구 메모리 예약 인스턴스와 동시에 예약을 운영하지 않으며 전환 중 가입·닉네임 쓰기를 필요에 따라 잠시 닫는다.
5. 구 웹의 허용 Origin JSON 요청·쿠키 전달·실제 이메일 인증 후 가입 증명 보존을 확인한다.
6. 웹·모바일에 인증 → 동의 → 프로필 상태 분기, 자격 전달과 3분 닉네임 예약 계약을 적용한다.
7. 약관을 설정한 스테이징에서 이메일 가입, 중단 후 로그인 재개, 기본 캐릭터 그대로 완료, 미완료 회원 제한, 구 가입 차단을 확인한다.
8. 준비된 클라이언트에 신규 가입을 활성화한다. 구 가입·가입 코드 발송·가입 목적 코드 확인의 동의 우회가 닫히는지 확인한다.

가입 증명은 인증 성공 후 고정 10분에 만료된다. cleanup 주기는 만료 시각을 늘리지 않는다. `REQUIRED` 회원 자체는 만료 정리 대상이 아니다. 프로필 완성 기한을 제한하거나 중단한 회원을 삭제하지 않는다.

가입 만료 정리는 별도 `READ_COMMITTED` 트랜잭션이다. MySQL binary log 사용 시 `binlog_format`은 `ROW` 또는 `MIXED`여야 한다. `STATEMENT`는 이 격리 수준의 쓰기와 호환되지 않는다. 일반 가입 쓰기의 격리 수준을 전역 변경하지 않는다.

웹 증명 쿠키는 DB 증명의 실제 남은 시간으로 설정한다. 만료·무효·구 가입 증명 또는 탈퇴·삭제 회원의 잔존 증명 조회는 200 인증 시작 상태와 쿠키 정리로 복구한다. 회원 생성 후 세션을 잃으면 갱신 또는 기존 로그인으로 같은 회원을 복구한다.

## 장애와 중지

| 상황 | 대응 |
| --- | --- |
| 신규 가입 중지 | `signup.enabled=false`와 `signup.legacy-signup-enabled=false`를 함께 적용해 구 동의 우회 경로를 다시 열지 않음 |
| DB 장애 | 가입·동의·예약 쓰기를 실패 처리. Redis나 메모리로 우회하지 않음 |
| 메일 장애 | 인증 성공으로 표시하지 않으며 발송 제한을 유지하고 새 발송 요청 안내 |
| 기본 캐릭터 누락 | 회원·동의 생성 전체 롤백. 카탈로그 복구 후 같은 유효 증명으로 재시도 |
| 닉네임 충돌·예약 만료 | 409 응답과 중복 확인 재요청. 실패 시 기존 예약 유지 |

롤백은 기능 진입을 닫고 현재 스키마·데이터·프로필 접근 제어를 유지한다. 새 상태를 모르는 과거 바이너리는 미완료 회원의 서비스 접근과 DB 예약을 우회할 수 있다. 테이블 삭제나 회원 일괄 삭제를 롤백 절차로 사용하지 않는다.

## 관찰과 검증

신규 가입 실패, 코드 재시도 한도, 기본 캐릭터 해석 실패, 닉네임 충돌, DB 잠금 대기와 `REQUIRED` 회원 수를 관찰한다. 테스트의 동시 실행 성공을 운영 처리량 보장으로 해석하지 않는다. 토큰·인증 코드·쿠키·비밀번호·이메일을 원문 요청 로그에 남기지 않는다.

일반 Gradle 테스트와 실제 MySQL migration 태그 테스트를 구분한다. H2만으로 MySQL 닉네임 collation, 고유 제약과 마이그레이션을 입증하지 않는다. 공통 소셜 증명 테스트는 검증된 신원을 fixture로 제공하며 외부 제공자 로그인을 뜻하지 않는다.

활성화 전 실제 메일 전달, 갱신 세션 저장, 웹·API 도메인의 HTTPS 쿠키·Origin·CORS, 약관 본문·버전, 캐릭터 ID·자산, 적용 스키마·격리·binary log 조건을 별도로 확인한다. 이 변경에는 외부 로그인 진입점이 없으며 외부 인증은 후속 변경과 별도 활성화로 제공한다.

## 소셜 이메일 보완 제거 전환

- 적용된 V17과 기존 회원·소셜 연결·동의 데이터는 수정하지 않는다. `verified_email`의 DB nullable 속성과 `verification.signup_proof_hash` 컬럼은 호환을 위해 남긴다.
- 새 SOCIAL 증명은 제공자 이메일이 필수다. 이메일 없는 과거 SOCIAL 증명은 직접 소비에서 `PROOF_INVALID`, 진행 조회에서 `AUTHENTICATE`로 돌아가며 만료 정리 대상으로 남긴다.
- 새 일반 이메일 challenge에는 소셜 proof를 저장하지 않는다. 과거 `signup_proof_hash`가 있는 challenge의 재발송·일반 이메일 인증은 `CHALLENGE_INVALID`로 거절한다.
- 웹·모바일의 `/signup/social/email` 매핑을 제거하고 `VERIFY_EMAIL`을 더 이상 반환하지 않는다. 클라이언트의 화면·라우팅·호출도 함께 제거한 뒤 활성화한다. 새 OAuth 가입 오류 `EMAIL_REQUIRED`·`INVALID_EMAIL`은 인증 시작으로 복구한다.
- 일반 이메일 인증·재발송 제한, 이전 증명·challenge 재사용 거절, 동의 원자성·기존 회원 재진입을 검증한다. 제공자 이메일 수용 확대로 기존 계정 자동 연결 보호 조건을 완화하지 않는다.
